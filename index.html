How it stays fresh

The update.yml workflow runs monthly, fetches the Debian iso-codes derived iso_3166-2.json database, regenerates the JSON and commits only when the data actually changed. GitHub Pages serves the result. No server to run.

Data source and accuracy

The source is the iso-codes subdivision database as published by the php-isocodes-db project, mirroring the Debian iso-codes package and tracking the official ISO 3166-2 standard. All 5,046 entries are included: 1,181 provinces, 646 districts, 517 municipalities, 474 regions, 279 states and 104 further categories, covering 200 parent countries.

Limits, stated plainly

  • Subdivision type strings are the source's English labels and are not normalised — 109 distinct values.
  • Codes reflect the current ISO table only; retired codes are not included.
  • Names follow the ISO transliteration, so some differ from local spellings.
  • The ISO standard updates irregularly, so the monthly workflow may go many runs without a commit.
